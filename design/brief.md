# workbuddy-bridge 介绍页 · 设计简报

> 2026-11-10。项目：`github.com/Huichao007/workbuddy-bridge`
> 目的不是"好看"，是**让一个陌生人在 15 秒内看懂并点 Star**。

---

## 1. 一句话

- 产品是什么：把 WorkBuddy 桌面端已登录的订阅积分，变成 OpenAI 兼容的本地接口，让 OpenCode / Codex CLI / Cursor 直接用上，不需要 API key。
- 给谁用：已经在付 WorkBuddy 订阅、同时又在用 Claude Code / Codex / Cursor 的开发者（中文为主，Windows）。
- 用户来这里**只做一件事**：判断"这东西能不能让我一份积分喂两个客户端"，然后决定装不装。
- 明确不做什么：不是代理网关，不是多账号池，不是 API 转售，不做云端中转。

## 2. 要传达的一件事

> **一份 WorkBuddy 积分，OpenCode 和 Codex CLI 同时花，不填一个 API key。**

这句话必须出现在首屏，且是首屏字号最大的那一行。

## 3. 平台与尺寸

- [x] Web 落地页（桌面 1440 / 平板 768 / 手机 390）
- 单页长滚动，无路由

## 4. 风格

- 参照：Linear（暗色原生、极简、单一强调色、发丝边框）
- 要像：工程精密感、安静、信息密度高但不吵
- 不要像：AI 味模板页（紫蓝渐变 + 玻璃拟态 + 三个等高卡片 + 居中标题）
- 情绪词：可信、克制、可验证
- 设计系统：`assets/design-systems/linear-app/DESIGN.md`

## 5. 内容与数据

- 真实数据来源：`README.md` 实测输出、`GET /v1/models` 现读、本机 `/health`
- 首屏三块数字（必须真实）：
  - `22` 个模型（现读 `/v1/models`）
  - `0` 个 API key（架构事实）
  - `2` 个客户端同时可用（OpenCode + Codex）
- 极端情况：模型数会变（会掉到 18）；用户只装国际版；桌面端没登录 → 这些都要有对应文案，不能写死 22。

## 6. 硬约束

- 品牌色：单色强调，深色底；除强调色与状态色外全灰阶
- 禁用：紫蓝渐变、玻璃拟态、发光边框、三卡片横排、emoji 当图标
- 合规：**必须**保留"非官方、可能违反服务条款、自行承担风险"的醒目说明，且不放在页脚小字里
- 不用 A 股涨跌色（这是工具页，不是行情页）

## 7. 交付

- 屏：1 屏长页，分 7 个区块
- 可点原型：不需要
- 代码：单文件 `index.html`（无构建、无外部依赖、可直接开）
- 配图：**下面这张架构图是本案主角**，必须是手写 SVG，不许截图、不许外部图片
